# x1080x 普通页面抓取

## 当前行为

列表和详情统一使用普通 Discuz 入口，不再附带 `archiver=1`，不自动回退 archiver。
分类列表保留 `fid`、`typeid`、`page`，增加 `orderby=dateline`，按发帖时间倒序。
已有公共会话池、固定代理线路、Cookie/UA 复用、请求节流和 CF 验证处理继续使用。

2026-10-15 的只读访问确认：普通列表能在浏览器自动验证后加载；免费期内详情返回磁链，
超过 6 小时的样本在原始 HTTP 200 HTML 中已被会员提示替换。抓取普通页不能保证游客可以读取历史磁链。

失败类型分别处理：

| 类型 | 行为 |
| --- | --- |
| `cf_challenge` | 使用已配置的验证服务；保持已有失败重试策略 |
| `cf_blocked` | 明确封锁，不再送去反复解题或限流冷却；详情保留失败台账，停止自动重试 |
| `rate_limited` | 真正限流沿用冷却；增量停止本轮，补抓等待后重试原目标 |
| `membership_required` | 正文明确显示 VIP 下载限制且没有磁链；保留失败台账，停止自动重试 |
| `missing_magnet` | 没有明确会员提示的缺磁链页面，仍按一般详情异常记录 |
| `invalid_list` | 页面结构、分页号或空列表证据不成立，不能作为正常到底 |

停止自动重试的记录沿用台账 `exhausted` 状态，管理页显示“已停止”；失败计数保持真实值，
不伪造达到次数上限。取得权限或解除封锁后，可手动重新入队。JSON 和 MongoDB 使用同样策略，
不新增数据库字段，不需要迁移已有记录。

增量任务仍会扫描配置的近期页面；“停止自动重试”指失败台账调度，不意味着屏蔽该帖子未来的正常发现。
旧记录里的 `missing_magnet` 等错误不会被批量改写，下一次真实抓取识别到权限限制后才停止自动重试。

## URL 与历史进度兼容

- 重试旧失败记录时按 `source_key` 重建当前域名的普通详情 URL，不再发送旧 archiver URL。
- 不批量更新已有资源 URL，不删除或回填资源记录；正常成功/失败写入沿用原有台账生命周期。
- 列表必须具备 `#threadlist`；空列表还必须有明确的“尚无主题”等提示。
- 检查当前页码、明确末页及重复页面，异常列表不推进检查点；明确末页不再多请求一页。
- 非目标列表只重试一次，重试失败保留失败状态，不能误报已到底。
- 历史补抓改用 `fid=<fid>;normal;orderby=dateline;v1` 检查点范围，保留原 archiver 检查点，
  不直接复用旧页码；新页码语义下重新扫描，已入库帖子仍按 `tid` 去重。
- 历史补抓遇明确封锁或会员限制时保存已完成结果、停止后续分类，当前页检查点不推进。
  不建议在游客状态下重新启动大范围历史补抓。

## 部署配置

只更新了 `config/config.example.yaml`，未修改本机私有配置或生产调度。已有部署需显式合并：

```yaml
crawler:
  sources:
    x1080x:
      concurrency: 1
      per_proxy_concurrency: 1
      rate_limit:
        min_interval_seconds: 2
      schedule:
        cron: "*/20 * * * *"
```

以上为低并发试运行起点，不是站点公布或已验证的配额。根据发帖量配置 `x1080x.page_limit`，
保证两次轮询间的新帖仍在扫描范围内；站点维护、验证失败或断网可能使资源错过 6 小时免费窗口。
已有每日一次的调度不会因示例文件更新自动改变。

本次没有接入 VIP 登录、账号 Cookie 管理、持久浏览器抓取或其他站点资源补全。
这些链路需要独立验证账号权限与会话行为。
